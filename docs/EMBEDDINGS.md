# 한글·영어 기억을 임베딩으로 찾아 채팅에 반영하기

아래 안내는 공개 기억만 담은 책을 대상으로 합니다. **2.1.1-st.1에서 비밀 기억이 있는 관리 책은 벡터 수집에 등록하지 마세요.** 외부 검색 경로의 인물 필터 보호는 아직 검증되지 않았습니다. 확장이 만드는 항목은 기본적으로 vectorized:false입니다.

SillyTavern 1.19.0의 기본 **Vector Storage(벡터 저장소)**를 사용합니다. 기억 보관함의 코드를 바꾸거나 별도 벡터 확장을 설치할 필요는 없습니다.

```text
기억 보관함에서 저장 → 현재 채팅의 World Info 갱신
                                    ↓
일반 채팅 응답 생성 → 새로 생기거나 바뀐 항목 임베딩
                                    ↓
최근 대화의 의미로 관련 항목 검색 → World Info 예산 안에서 프롬프트에 포함
```

임베딩은 모델을 재학습시키는 기능이 아닙니다. 현재 대화와 관련 있는 기억을 골라 답변 요청에 함께 넣는 검색 기능입니다. 예를 들어 영어로 저장한 열쇠의 은닉 장소를 한국어 질문으로 찾는 데 사용할 수 있습니다. 검색 성공률은 모델과 기억 내용, 검색 설정에 따라 달라집니다.

## 1. 제공자와 모델 선택

**API 연결(API Connections)**에서 사용할 제공자의 키를 저장하고, **확장 → Vector Storage**에서 **Vectorization Source / Vectorization Model**을 선택합니다. 키는 SillyTavern에 입력하며 기억 보관함에는 입력하지 않습니다.

| 제공자 선택 | 시작할 모델 | 참고 |
| --- | --- | --- |
| OpenAI | `text-embedding-3-small` | 한글·영어 혼합 검색의 시작점으로 추천. 필요하면 `text-embedding-3-large`와 비교합니다. |
| Google AI Studio | `gemini-embedding-001` | Google API 키를 쓰고 싶을 때 선택합니다. |
| OpenRouter | 목록에 있으면 `openai/text-embedding-3-small` 또는 `openai/text-embedding-3-large` | 사용 가능한 임베딩 모델 목록에서 선택합니다. |
| NanoGPT | 목록에 있으면 `text-embedding-3-small` | 사용 가능한 임베딩 모델 목록에서 선택합니다. |

네 제공자 모두 확인한 SillyTavern 1.19.0에 연결 항목이 있습니다. OpenRouter와 NanoGPT의 모델 목록은 제공자가 반환하므로 계정·서비스 상황에 따라 달라질 수 있습니다. 오래된 SillyTavern에서 항목이 보이지 않으면 버전을 확인하세요.

**답변을 만드는 채팅 모델과 임베딩 모델은 별개입니다.** 예를 들어 답변에는 OpenRouter의 Claude를, 기억 검색에는 OpenAI 임베딩을 사용할 수 있습니다. 임베딩 제공자의 키를 저장한 뒤 평소의 채팅 연결로 돌아가도 됩니다. 대화용 모델 이름을 임베딩 모델 칸에 넣지는 마세요.

외부 API를 선택하면 활성 로어북 내용과 검색에 쓰는 최근 메시지가 해당 제공자에게 전송됩니다. 임베딩 호출의 비용·한도는 채팅 생성과 별도이며 제공자 정책을 따릅니다.

## 2. World Info 검색 켜기

**확장 → Vector Storage → World Info settings**에서 다음을 설정합니다. 번역에 따라 이름이 다를 수 있어 영문도 함께 적었습니다.

| 설정 | 시작값 |
| --- | --- |
| Enable for World Info · 월드인포에 활성화 | 켬 |
| Enabled for all entries · 모든 항목에 활성화 | 켬 |
| Query messages · 검색에 사용할 최근 메시지 수 | `2` |
| Max Entries · 검색으로 활성화할 최대 항목 수 | `5` |
| Score threshold · 관련성 점수 하한 | 기본값 `0.25`에서 시작 |

`Query messages`와 `Score threshold`는 같은 벡터 저장소 패널의 공통 설정에 있습니다. 검색이 주변 맥락을 놓치면 메시지 수를 `3~4`로 늘려 비교하세요. 엉뚱한 기억이 많이 나오면 점수 하한을 올리고, 관련 기억이 안 나오면 낮춰 비교합니다. 점수의 의미는 모델마다 달라 모든 모델에 맞는 최적값은 없습니다.

**현재 기억 보관함에는 ‘Enabled for all entries’가 필요합니다.** 자동 관리 항목을 개별 🔗 상태로 바꾸는 방식은 사용하지 마세요. 확장이 다시 구성하는 항목에는 수동 변경이 유지되지 않습니다. 이 전체 옵션은 보관함뿐 아니라 **현재 채팅에 연결된 다른 활성 로어북**에도 적용됩니다. 저장해 둔 모든 미연결 로어북을 검색하는 것은 아닙니다.

`MemoryVault_<해시>` 파일을 채팅/글로벌 로어북에 직접 연결할 필요는 없습니다. 확장이 현재 채팅의 기억을 자동으로 연결합니다. 별도로 가져온 일반 로어북은 평소처럼 채팅·캐릭터·글로벌 로어북 중 적절한 곳에 연결해야 검색 대상이 됩니다.

로어북 검색만 원한다면 **Enable for chats**, **Enable for files**는 켤 필요가 없습니다. **Include in World Info Scanning**은 검색된 채팅/파일 내용으로 로어북 키워드를 추가 검색하는 설정이며, 로어북 임베딩을 켜는 설정과 다릅니다. **Vectorize All**도 채팅 기록용 버튼이므로 이 작업에는 필요하지 않습니다.

## 3. 저장 후 평소처럼 대화하기

기억 보관함에서 기억을 저장하고 일반 채팅 메시지를 보내세요. 답변 생성 과정에서 새 항목·변경된 항목을 자동으로 임베딩하고, 최근 메시지와 관련 있는 내용을 검색합니다. 첫 실행이나 많은 내용을 수정한 직후에는 추가 시간이 걸릴 수 있습니다.

2026-10-14 개정: 가져온 인물 범위 확인 대기 및 지원하지 않는 제한 기록은 활성 기억 목록에서 제외되어 검색/추출 재료로 사용하지 않습니다. 원본은 격리 데이터로 내보낼 수 있습니다.

키워드 검색도 계속 작동합니다. 벡터 검색을 켜면 **키워드가 일치하지 않아도 의미가 비슷한 항목이 활성화될 수 있습니다.** 따라서 기존의 키워드/AND 조건만으로 발동을 제한하고 싶은 항목에는 이 동작이 맞지 않을 수 있습니다.

검색된 항목도 **World Info 토큰 예산**의 영향을 받습니다. `Max Entries = 5`는 벡터 검색의 선택 한도이며, 상시 항목과 키워드로 활성화된 항목을 포함한 전체 주입량을 5개로 제한하는 뜻은 아닙니다.

## 4. 한글 표시본과 영어 원문

현재 포팅 버전은 **원문을 World Info에 넣고, 한국어 표시본은 보관함 화면에서 보여 줍니다.** 따라서 영어 원문에 딸린 한국어 표시본까지 별도로 임베딩하는 구조는 아닙니다. 원문 자체가 한국어라면 한국어 원문이 대상입니다.

다국어 임베딩은 한국어 질문과 영어 원문의 의미를 비교할 수 있으므로 같은 기억을 한글·영어 두 항목으로 중복 저장할 필요는 없습니다. 중복 항목은 검색 슬롯과 프롬프트 예산을 낭비할 수 있습니다. 별개의 한글/영어 로어북에 서로 다른 정보가 있다면 둘 다 연결해서 검색하면 됩니다.

보관함의 전체 주입을 끄면 해당 기억도 검색 대상에서 빠집니다. 비활성 구조화 백업, 이미지, AI 참조 제외 문서는 임베딩 대상으로 전달하지 않습니다.

## 5. 반영 확인과 조정

1. 조건부 기억 하나에 원문 `Mira hid the silver key beneath the old oak tree.`를 넣고 영어 키워드 `silver key`를 지정합니다.
2. 한국어로 `미라가 열쇠를 어디에 숨겼더라?`처럼 관련 질문을 보냅니다.
3. 생성 요청의 프롬프트 상세에서 해당 원문이 World Info 내용에 포함됐는지 확인합니다. 그럴듯한 답변만으로 검색 성공을 판단하지 마세요.
4. 안 들어갔다면 보관함 저장/주입 상태, API 키와 모델, 위의 두 활성화 옵션, 점수 하한, World Info 예산을 차례로 확인합니다. API 오류가 있으면 SillyTavern 서버 로그도 확인하세요.

아주 긴 위키 문서는 주제별로 나누는 편이 좋습니다. World Info 임베딩은 개별 항목의 본문을 입력으로 보내므로, 파일용 청크 설정만으로 긴 로어북 항목이 자동 분할되지는 않습니다.

모델을 바꾸면 SillyTavern은 제공자/모델별 인덱스를 사용합니다. 처음 선택한 모델에서는 다시 임베딩하므로 시간과 비용이 발생할 수 있습니다. 이후 검색에도 같은 설정을 유지하세요.
