MEMORY VAULT · 그림으로 이해하기

한글로 물어도,
영어로 저장한 기억을 찾을 수 있어요.

다국어 임베딩은 문장의 뜻을 비교해서 기억을 찾습니다.
찾은 기억의 원문을 대화 AI에게 함께 보내는 방식이에요.

이해를 돕는 예시 화면 · 실제 설정이나 API를 바꾸지 않습니다
1

한 기억에 ‘원문’과 ‘읽기용 번역’이 있어요.

예를 들어 보관함이 이 기억을 영어로 작성했다면:

저장된 원문 · 영어

Mira hid the key
under the old oak tree.

검색 대상 → 대화 AI에게 전달
보관함에서 내가 읽는 번역 · 한글

미라는 열쇠를
오래된 참나무 밑에 숨겼다.

같은 기억을 읽기 쉽게 표시

같은 내용이므로, 검색용 기억을 두 개 만들 필요가 없어요.

내가 채팅에 입력
“미라가 열쇠를 어디 숨겼더라?”
뜻으로 검색한글 질문 ↔ 영어 기억
→
영어 원문 발견찾은 원문을 그대로 사용
→
대화 AI가 읽음현재 대화 + 찾은 기억
답변 예시　“오래된 참나무 밑에 숨겼어.”

원문이 한국어라면 한국어 원문을 검색·전달합니다. 여기서는 한영 검색이 성공한 상황을 그렸으며, 실제 검색·답변은 모델과 설정에 따라 달라집니다.

2

‘모든 항목’은 어디까지 찾는다는 뜻일까요?

지금 채팅에 연결된 로어북의 활성 항목까지 검색한다는 뜻이에요.

World Info 검색 켜짐모든 항목 검색 켜짐
현재 채팅의 기억 보관함
확장이 자동으로 연결
✓ 검색 대상
캐릭터 설정 로어북
내가 현재 채팅에 연결한 책
✓ 이것도 검색 대상
다른 이야기의 로어북
저장만 하고 연결하지 않은 책
검색 대상 아님

현재 보관함 + 연결된 캐릭터 설정 로어북을 함께 검색해요.

‘내가 가진 모든 로어북 파일’을 뒤지는 뜻은 아닙니다. 비활성 항목과 보관함의 AI 참조 제외 문서는 대상에서 빠집니다.

서로 다른 정보가 담긴 한글·영어 로어북이라면, 둘 다 연결하면 돼요.

3

외부 API에는 무엇이 전달될까요?

‘기억을 찾는 서비스’와 ‘답변을 만드는 모델’을 나눠 보면 쉬워요.

① 기억 찾기 담당 · 임베딩 API

검색할 내용을 받아
의미를 비교할 숫자로 바꿔요.

예: OpenAI / Google / OpenRouter / NanoGPT

검색 대상인 로어북 내용처음 등록하거나 내용이 바뀔 때 전송
최근 대화 메시지지금 어떤 기억을 찾을지 정할 때 전송

이 숫자를 이용한 유사도 검색은 SillyTavern 쪽에서 진행합니다. 외부 API를 선택하면 위의 텍스트가 해당 서비스로 나갑니다.

② 답변 담당 · 평소 쓰는 채팅 모델

대화에 찾은 기억을 더해서
답변을 만들어요.

예: 평소 연결한 Claude / Gemini / GPT

평소 보내는 대화와 설정
+ 열쇠를 숨긴 장소검색된 기억의 원문
공간 부족: 함께 발견한 다른 기억이번 요청에서는 빠진다고 가정

World Info 예산 = 기억을 넣을 수 있는 분량 한도. 관련 기억을 찾아도 공간이 모자라면 일부는 빠질 수 있어요.

공간 그림은 원리를 단순화한 예시입니다. 실제 예산은 토큰으로 계산하며 항목 길이·우선순위·상시 기억 등도 영향을 줍니다. 두 담당에 서로 다른 제공자를 선택해도 됩니다.

기억은 원문으로 저장하고,
다국어 검색으로 필요한 기억을 찾아,
들어갈 공간만큼 대화 AI에게 함께 보내는 것이에요.

실제 설정 순서: 한글·영어 임베딩 사용 안내

기준: Memory Vault 2.0.0-st.1 및 SillyTavern 1.19.0. SillyTavern 검색 코드 · 확장 World Info 변환 코드

이 화면의 조작은 설명용입니다. 저장된 기억, 실제 설정, API에 영향을 주지 않습니다.
