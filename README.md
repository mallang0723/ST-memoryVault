# 기억 보관함 · Memory Vault for SillyTavern

Marinara용 **기억 보관함 v2.1.1**의 플랫폼 독립 기능을 **SillyTavern 1.19.0 이상**으로 옮긴 `2.1.1-st.3` 개발판입니다. 서버 플러그인, Extras 서버, 별도 빌드는 필요하지 않습니다.

약속, 기억 앵커, 요소 기억, 이야기 위키, 장면, 진행 흐름의 여섯 계층을 관리합니다. 한국어 표시본, 테마, 후보 검토와 보관함 내부 편집 잠금을 유지합니다. 현재 열린 **개인 채팅과 그룹 채팅**을 대상으로 합니다.

장면·흐름 후보는 기존 Summarize/수동 원문 정리 호출에서 함께 생성합니다. 인물 범위는 avatar ID로 저장하며, 가져온 알 수 없는 ID는 보존하고 주입을 보류합니다. 편집 창의 미해결 ID를 실제 인물로 바꾸고 범위를 확인하세요. APPEND와 APPEND_DISABLED 그룹에는 비밀 기억을 넣지 않습니다.

분기 끝점은 저장된 원문 경계 지문이 일치할 때만 인정합니다. 증거가 없거나 원문이 달라졌으면 상속 기억 전체를 확인 대기로 옮깁니다. 근거 수정·삭제는 기존 기억의 주입을 유지하면서 재검토로 표시합니다. 상시 예산은 기본 OFF이며 중요 기록은 상한보다 우선합니다. ST 전역 WI 토큰 예산과 별개입니다.

| 기능 | ST 대응 |
| --- | --- |
| 장면·흐름·범위·선택·근거 감시 | 보관함 UI와 현재 채팅 metadata |
| 모델 호출 | ST 현재 연결, 추가 키 입력 없음 |
| 고급 메모리 AM / Keeper | 미지원, 전용 API 호출 없음 |
| 관리 WI 잠금 | ST 잠금 계약 없음, 직접 편집 충돌 시 동기화 중단 |

이 저장소는 개인 포팅 프로젝트이며 **SillyTavern·Marinara Engine의 공식 확장이 아닙니다.** 원본은 [원 게시글 작성자의 Marinara 확장 「기억 보관함」](https://m.dcinside.com/mini/aichatfrontend/162)입니다. 원본의 MIT 고지문과 2026-10-06 원작자의 커뮤니티 공유용 SillyTavern 이식 허락은 [NOTICE](NOTICE.md)에 기록했습니다. 이 저장소의 `LICENSE`는 AGPL-3.0으로 유지하며 원본 MIT 고지를 함께 보존합니다.

## 설치

1. SillyTavern **1.19.0 이상**에서 **확장 → 확장 설치**를 엽니다.
2. 아래 저장소 주소를 붙여 넣고 설치합니다.
3. SillyTavern을 새로고침하고 채팅을 연 뒤 **기억 보관함**을 엽니다.

```text
https://github.com/mallang0723/ST-memoryVault
```

ZIP으로 수동 설치할 때는 아래 위치에 풉니다. `manifest.json`이 확장 폴더 바로 아래에 있어야 합니다. 이미 ZIP으로 설치했다면 같은 확장을 다른 폴더에 중복 설치하지 마세요.

```text
SillyTavern/
└── public/scripts/extensions/third-party/memoryVaultSilly/
    ├── manifest.json
    ├── index.js
    ├── extension.js
    ├── extension.css
    ├── host.js
    ├── links.js
    ├── world-info.js
    └── migration.js
```

GitHub 주소로 설치한 버전은 SillyTavern의 확장 관리 화면에서 업데이트할 수 있습니다.

## 사용

1. SillyTavern에서 캐릭터 또는 그룹의 채팅을 엽니다.
2. 오른쪽 **기억** 버튼, 확장 메뉴의 **기억 보관함**, 또는 확장 설정의 **보관함 열기**를 누릅니다.
3. 약속·앵커·요소·위키를 직접 작성하거나, 대화를 골라 AI 후보를 만듭니다.
4. 저장하면 현재 채팅 전용 World Info 파일이 동기화됩니다.

AI 기능은 **SillyTavern에서 현재 선택한 API와 모델**을 사용합니다. API 키를 이 확장에 다시 입력하지 않습니다. 연결이 없어도 수동 편집·검색·가져오기·내보내기는 가능합니다. Marinara의 개별 모델 연결 ID는 이전하지 않습니다.

다른 이야기의 기억을 편집하려면 SillyTavern에서 해당 채팅을 여세요. 열지 않은 채팅의 기억은 편집하지 않습니다. 예외적으로 옛 관리 책 이름을 이전할 때는 그 책을 직접 연결해 둔 다른 채팅의 로어북 연결 이름만 바꾸고 저장·재읽기로 확인합니다. 메시지는 변경하지 않습니다.

## Marinara 기억 데이터 이전

설치 ZIP에는 확장 코드만 들어 있습니다. 이전 RP의 실제 기억은 별도로 가져와야 합니다.

**보관함 → 설정 → 로어북 → JSON 가져오기**에서 다음 형식을 지원합니다.

- `memoryCabinetV1` 데이터 자체 또는 이를 포함한 채팅 `metadata` JSON
- 비활성 **기억 보관함 · 구조화 백업** 항목이 들어 있는 Marinara/ST 로어북 JSON
- 이 확장의 **JSON 내보내기** 파일

확인 후 현재 채팅의 보관함을 교체합니다. 이전 소유 채팅 ID와 로어북 연결 ID는 현재 채팅에 맞게 다시 생성합니다. 기존 기억이 있으면 교체 전 JSON 다운로드와 `chat_metadata.memoryVaultImportBackup`에 직전 사본을 남깁니다. 원본 메시지와 요약은 수정하지 않습니다.

가져온 제한 기억은 일치하는 인물 ID도 설정의 ‘가져온 인물 범위 확인’에서 명시적으로 확인해야 복원됩니다. 실제 인물 ID를 선택하거나 기존 ID를 유지할 수 있으며 빈 선택은 공개로 변환하지 않습니다. 미해결 ID와 지원하지 않는 요소/위키 범위는 원본 그대로 격리 보존하고 주입·건강검진·위키·직접 추출에서 제외합니다. 장면/흐름에 제한된 하위 기록이 있으면 해당 장면/흐름 전체가 대기합니다. 관리 WI는 마지막 저장 결과 전체와 비교합니다. 기준 없는 2.0.0 책은 저장된 구조화 책과 기존 템플릿으로 옛 컴파일 결과를 재구성해 일치할 때만 자동 이전합니다. 직접 수정 또는 재구성 불가 시 충돌로 중단하고 원본을 보존합니다. 같은 채팅의 재가져오기는 같은 책 ID를 사용하므로 충돌 해결을 보장하지 않습니다.

원문과 한국어 표시본은 각각 보존하며, 모델에는 원문만 주입합니다. 잘못된 JSON, 여러 채팅이 섞인 입력, 10 MiB를 넘는 파일은 적용하지 않습니다. 첨부한 설치 ZIP 자체는 기억 데이터로 가져올 수 없습니다.

## 저장과 주입

- 원본 기억: 현재 채팅의 `chat_metadata.memoryCabinetV1`
- 화면·자동화 설정: SillyTavern `extensionSettings.memoryVault`
- 동기화 결과 및 비활성 구조화 백업: World Info의 `기억보관함 - <캐릭터명> - <채팅 이름> (<짧은 꼬리>)` 파일
- 직전 JSON 가져오기 백업: `chat_metadata.memoryVaultImportBackup`

`기억보관함 - …` 파일은 확장이 관리합니다. **채팅 로어북이나 글로벌 로어북에 직접 연결할 필요가 없습니다.** 기존에 연결한 사용자 로어북은 그대로 두고, `WORLDINFO_ENTRIES_LOADED` 이벤트로 현재 채팅의 기억을 함께 스캔합니다. 확장이 꺼져 있으면 이 자동 연결도 중단됩니다.

그룹 채팅은 캐릭터명 대신 그룹 이름을 씁니다. ST 기본 채팅명 `캐릭터명 - YYYY-M-D @HHh MMm SSs mmms`는 날짜만 `YYYY-MM-DD`로 표시합니다. 직접 바꾼 채팅명은 유지하되 앞에 같은 캐릭터명(그룹명)이 붙어 있으면 중복 접두사 한 번만 뺍니다. 꼬리는 채팅 키 SHA-256의 앞 6자이며 충돌 시 2자씩 늘립니다. 파일명 금지 문자·제어 문자를 정리하고 UTF-8 파일명 길이를 제한하되 한글과 공백을 유지합니다. 표시 이름은 생성 시점 기준으로 고정합니다(아래 구버전 이름 이전 제외). 캐릭터·채팅 이름을 바꿔도 책을 다시 만들거나 이름을 자동으로 바꾸지 않습니다. 식별은 이름이 아닌 책 내부 `extensions.memoryVault.chatId`와 안정적인 내부 ID를 사용합니다.

기존 `MemoryVault_<해시>` 책과 현재 캐릭터·채팅명으로 생성된 2.1.1-st.2의 긴 이름 책은 해당 채팅의 다음 동기화 때 새 규칙 이름으로 자동 이전합니다. 사용자가 직접 바꾼 책 이름은 유지합니다. 새 이름으로 전체 JSON을 저장·재읽기해 이름 외 내용·엔트리·확장 데이터가 일치하는지 확인하고, 직접 연결한 채팅·글로벌·보조 캐릭터·페르소나 연결을 저장·검증한 뒤에만 옛 파일을 제거합니다. 실패 시 옛 책을 보존합니다. 중단 후 남은 사본은 원본과 같을 때만 재사용하며, 서로 다르면 두 책을 보존하고 멈춥니다. 캐릭터 **기본** 로어북으로 연결한 경우에는 카드의 연결을 새 책으로 직접 바꾼 뒤 다시 동기화하세요. 같은 채팅의 관리 책이 임의로 복제된 경우에도 자동 선택하지 않습니다. 내부 연결 ID에 옛 해시가 남는 것은 정상입니다.

약속·상시 앵커·위키 상시 개요는 상시 항목으로, 키워드 앵커·요소·위키 본문은 조건부 항목으로 변환됩니다. 조합 조건은 모든 단어가 있어야 발동하며, SillyTavern의 전역 재귀 검색을 켤 필요가 없습니다. 최근 4개 메시지를 검색하며 **실제 주입량은 SillyTavern World Info 예산의 영향을 받습니다.** 화면의 토큰 수는 추정치입니다. 큰 위키를 사용할 때는 World Info 예산도 확인하세요.

전체 주입을 끄면 조건부 항목도 포함해 보관함 기억을 주입하지 않습니다. 비활성 백업, 이미지, AI 참조 제외 문서는 주입하지 않습니다. 다른 채팅의 소유권이 붙은 데이터는 격리하고, SillyTavern이 만든 정상 분기는 새 소유권과 독립 로어북으로 상속합니다.

World Info의 자동 관리 항목은 보관함 화면에서 편집하세요. 본문·키·제목·상시 여부의 직접 편집 충돌이 발견되면 동기화를 중단합니다. 비관리 항목은 보존합니다. 비밀 기억을 포함한 책을 다른 확장의 장기 기억/벡터 수집 대상으로 등록하지 마세요. 외부 검색 경로의 인물별 비밀 보호는 검증되지 않았습니다.

한글·영어 기억을 의미로 검색하려면 SillyTavern의 기본 **Vector Storage**에서 **Enable for World Info**와 **Enabled for all entries**를 켜세요. OpenAI·Google·OpenRouter·NanoGPT 모델 선택과 설정 순서는 [임베딩 사용 안내](docs/EMBEDDINGS.md)에 정리했습니다. 이 옵션은 현재 연결된 다른 활성 로어북에도 적용됩니다.

[그림 설명 HTML](docs/embedding-visual-guide.html)을 내려받아 브라우저로 열면 원문·번역·검색 범위·AI 전달 과정을 눌러 보며 확인할 수 있습니다.

### 관리 World Info 직접 편집 충돌 해소 (2.0.0에서 업그레이드할 때도 적용)

2.0.0 안내의 ‘직접 편집하면 다음 동기화 때 덮어쓰기’와 달리, 2.1.1은 삭제·수정된 관리 항목을 발견하면 **먼저 멈추고 보존**합니다. 일반 ‘다시 동기화’는 충돌을 무시하지 않습니다.

1. SillyTavern World Info 편집기에서 해당 `기억보관함 - …` 책(이전 전에는 `MemoryVault_<해시>`)을 JSON으로 내보내 직접 편집 사본을 보존하세요. 보관함 JSON 내보내기는 직접 수정한 WI 사본을 대신하지 않습니다.
2. 유지할 직접 편집 내용을 기억 보관함의 해당 기억에 옮기세요.
3. **관리 WI 충돌일 때만** 보관함 **설정 → 로어북**(데이터 탭)에서 동기화 오류 아래 **보관함 기준으로 관리 항목 덮어쓰기**를 누르고 확인하세요. 버튼은 다른 동기화 오류에도 보이지만 네트워크·소유권 오류를 해결하지는 않습니다. 취소하면 쓰지 않습니다.
4. 이 동작은 해당 채팅의 관리 항목만 다시 생성하고 새 기준을 저장합니다. 비관리 항목·책의 외부 확장은 보존합니다. 이후 동기화에는 다시 충돌 보호가 적용됩니다. 동기화 중에는 먼저 끝날 때까지 기다리세요.

World Info 파일에는 비활성 구조화 백업과 비교 기준에도 비밀 원문이 들어 있습니다. 책 전체를 공유하면 그 원문도 함께 공유됩니다.

## 요약 및 자동화

SillyTavern **Summarize**가 메시지의 `extra.memory`에 저장한 요약을 읽습니다. 요약 생성 자체는 SillyTavern에서 설정합니다. 요약이 없어도 대화 원문 추출은 가능합니다.

기본 동작은 새 요약 알림과 사용자가 누르는 모델 정리입니다. 자동 분석·자동 적용을 선택하면 모델 호출 비용이 발생할 수 있습니다. 원본의 후보 검토, 변경 충돌 보호, 직전 자동 적용 되돌리기를 유지합니다. Marinara 전용 Memory Nag/LTM/Advanced Memory 에이전트 감지는 사용하지 않습니다.

모델 요청 중 채팅을 바꾸면 늦게 온 결과를 새 채팅에 적용하지 않습니다. 응답 시간 초과 후에는 이미 시작된 서버 요청이 끝날 때까지 재요청을 막습니다.

자동 적용을 선택해도 **비교 컨텍스트에 제한 기억이 포함된 회차는 전체를 검토 대기**로 전환합니다(약속·앵커·흐름·최근 장면의 제한 범위 포함). 새 요약이 공개이고 모델이 `knownBy`를 생략하거나 `all`로 답해도 자동 공개 저장하지 않습니다. 약속·앵커의 공개 후보는 범위 확인을 거쳐야 적용할 수 있으며 대기 후보의 표시는 재접속 후에도 유지됩니다. 이 보수적 전환은 설정을 영구 변경하지 않으므로 제한 컨텍스트가 없는 회차는 기존 자동화 동작을 따릅니다.

## 개발과 검증

실행 파일은 순수 ES 모듈입니다. 설치 시 `npm install`이나 번들링은 필요하지 않습니다. 개발용 테스트는 Node.js 22.8 이상을 사용합니다.

```sh
npm ci
npm run check
npm test
npm run package
```

실제 호스트 통합 테스트:

1. 별도 테스트 데이터 디렉터리로 SillyTavern 1.19+를 실행하고 이 확장을 설치합니다. QA 설정의 `browserLaunch.enabled: false` 또는 CLI `--browserLaunchEnabled false`로 브라우저 자동 열기를 끄세요.
2. 첫 사용자 설정을 완료하고 샘플 캐릭터 하나를 준비합니다. 오프라인 테스트에서는 연결 방식을 Chat Completion으로 설정합니다.
3. `ST_BASE_URL=http://127.0.0.1:8000 CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`를 실행합니다.

브라우저 테스트는 개인·그룹 테스트 채팅과 World Info 파일을 생성하므로 **격리된 테스트 데이터 디렉터리**를 사용하세요. 결과 이미지는 `test-results/`, 설치 ZIP은 `dist/`에 생성됩니다. 실제 유료 모델의 응답 품질은 자동 테스트 범위에 포함하지 않습니다.

자세한 호스트 매핑과 검증 범위는 [마이그레이션 기록](docs/MIGRATION.md)을 참조하세요.
